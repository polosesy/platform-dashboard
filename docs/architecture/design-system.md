# 디자인 시스템 — 원칙 v1과 토큰

웹 화면 전체의 글꼴·글자 크기·굵기·색·모서리·그림자·움직임 규칙입니다. 원본은 `apps/web/src/app/globals.css` 하나이고, `apps/api/test/designTokens.test.ts`·`palette.test.ts`가 지킵니다.

> **5살 비유**: 예전에는 방마다 다른 크레파스 25자루로 색칠해서 집이 어수선했어요. 이제 크레파스를 6자루로 줄이고 글씨도 한 가지 손글씨로 맞췄어요. 어느 방에 들어가도 같은 집처럼 보여요. 새 크레파스를 몰래 가져오면 테스트가 "그건 우리 상자에 없어요"라고 알려 줘요.

## 1. 원칙 v1

애플이 공개한 디자인 팁·디자인 리소스·Human Interface Guidelines와 애플 웹사이트 분석 글에서 원칙 24개를 뽑아 AUD에 대어 본 결과입니다(채택 16 · 변형 4 · 거부 4). 모양이 아니라 태도를 가져옵니다.

| # | 원칙 | 검사 질문 |
|---|------|-----------|
| 1 | **데이터가 주인공** — 색은 상태 뜻이 있을 때만, 그림자는 떠 있는 것만, 장식 없음 | 색을 지우면 뜻이 사라지는 곳에만 색이 있나 |
| 2 | **결론 먼저** — 화면마다 큰 것 하나(요약 문장 또는 핵심 숫자) | 3초 보고 괜찮은지 말할 수 있나 |
| 3 | **한 가지 일 = 한 가지 모양** — 패널·탭·칩·버튼은 UI 키트에서만 | 다른 메뉴의 같은 일이 같은 모양인가 |
| 4 | **사실만, 모르면 모른다고** — 0과 '모름'을 구분, 예시 데이터는 숫자보다 먼저 | 수집 실패가 0으로 보이는 곳이 없나 |
| 5 | **누구나** — 12px 이상 · 대비 4.5:1 · 키보드 · 움직임 줄이기 | 마우스 없이, 200% 확대로 끝까지 쓸 수 있나 |

거부한 것: 스크롤로 재생하는 이미지·전체 화면 사진, 흐림(블러) 패널, 재미 요소, 긴 이야기 구성 — 물건을 파는 페이지의 기법이라 데이터를 읽는 운영 화면에는 방해가 됩니다.

## 2. 글꼴

- **Pretendard**(한글·영문 한 벌, OFL) — `pretendard` 패키지의 dynamic-subset CSS를 `layout.tsx`에서 가져옵니다. 글꼴이 92조각(`unicode-range`)으로 나뉘어 페이지가 쓰는 글자의 조각만 받습니다. 빌드에 인터넷이 필요 없습니다.
- **Geist Mono** — 코드·ID·질의(`var(--font-mono)`).
- CSS 모듈의 `font-family`는 `var(--font-sans)`·`var(--font-mono)`·`inherit`만 씁니다.
- 애플의 SF Pro는 애플 기기 전용 라이선스라 웹에 묶을 수 없고, Windows에서는 맑은 고딕으로 보입니다. 그래서 Pretendard를 씁니다.

## 3. 글자 크기 6단계 · 굵기 4단계

| 토큰 | 크기 | 쓰는 곳 |
|------|------|---------|
| `--text-display` | 28px | 화면의 큰 것 하나(요약 문장·핵심 숫자) |
| `--text-title` | 20px | 페이지 제목 |
| `--text-heading` | 16px | 패널·절 제목 |
| `--text-body` | 14px | 본문·표 칸(`body` 기본값) |
| `--text-small` | 13px | 보조 줄 |
| `--text-caption` | 12px | 열 이름·라벨·칩·메타 |

- 굵기는 400·500·600·700만 씁니다.
- CSS 모듈에는 숫자 `font-size`를 쓰지 않습니다.
- TSX 인라인 `fontSize`는 위 숫자 중 하나만 씁니다.

**확대·축소되는 그림(캔버스)** — 라이브 다이어그램 카드, 구성도 타일, 서비스 맵 카드, 공격 경로·네트워크 맵의 SVG 글자, draw.io 내보내기에 해당합니다.
- 이 글자는 화면 픽셀이 아니라 그림 단위라서 줌에 따라 커지고 작아집니다.
- 그래서 `--canvas-text-xs`(10)·`--canvas-text-sm`(11)을 테스트의 허용 목록 파일에서만 씁니다.
- 줌 100%에서 12px을 지키는 카드 재설계는 다음 단계입니다.

## 5. 모서리 · 그림자 · 움직임

- **모서리** — 제어기 `--radius-sm` 6, 면 `--radius-md` 10, 알약 `--radius-pill`. 이 밖에는 0과 원(50%)만 씁니다.
- **그림자** — 면은 평평하게 두고 1px 테두리로 구분합니다. 떠 있는 것만 `--shadow-raise`(호버·끌기)와 `--shadow-pop`(메뉴·서랍·대화 상자)을 씁니다. 선택은 빛번짐 대신 고리 `--ring-accent`로 표시합니다.
- **움직임** — `--motion-fast` 150ms(눌림·호버), `--motion-base` 200ms(펼침·탭), `--motion-slow` 250ms(서랍)이고 모두 `--ease-out`입니다. 상태가 바뀔 때만 움직이고, `prefers-reduced-motion`이면 0입니다.
- **포커스** — 키보드 포커스는 공통으로 2px 파란 테두리(`:focus-visible`)입니다.

## 6. 바꾸는 순서

1. **토큰 + Pretendard + 12px 미만 금지** — 2026-11-09 완료.
   - 글자 크기 25종(8~11.5px 선언 324곳)을 6단계로, 굵기 12종을 4단계로, 모서리 30종을 3단계로 줄였습니다.
   - 흐린 그림자 20곳은 토큰으로 바꿨고, 고정폭 글꼴 선언 7가지는 하나로 합쳤습니다.
2. **UI 키트** — 2026-11-10 완료(아래 8절). 첫 적용 화면: AKS 모니터링 › SLO.
   - **화면 옮기기(진행 중)** — 2026-11-10: AKS 모니터링(SLO·수집 상태·노드·Pod 트래픽 머리줄)·비용·리소스 상태(글로벌·인스턴스 — 알림 하나에 권한 목록 접기, 숫자 카드 Stat, 상태 필터 Segmented·사용자 시작 제외 Toggle)·통합 위험(예시 알림 하나로)·AKS 클러스터(숫자 카드 7 → 4, 종류·네임스페이스 필터를 표 패널 머리로(근접성), 상태 Chip).
   - 남은 화면: 워크로드 히트맵·로그·리소스 상태 이벤트 탭·VNet 트래픽·AKS 보안 점검(직접 만든 카드 31)·Pod 트래픽(16)·보안 하위 화면·구성도/라이브 패널.
   - **래칫 테스트**: 키트 밖의 날 `<button>` 수와 화면 CSS가 직접 그리는 칩·배지 클래스 수는 파일마다 고정해, 늘어나면 테스트가 실패합니다. 여러 줄로 쓴 `<button`도 셉니다. 새 화면은 `Button`·`Chip`·`Badge`를 쓰고, 날 버튼이 정말 필요하면(펼치는 행·히트맵 칸) 숫자를 일부러 올립니다.
3. **`/login` 페이지 + 범위 막대** — 2026-11-10 완료.
   - 로그인은 **페이지 이동**(`loginRedirect`)으로 하고, 팝업은 쓰지 않습니다.
     - 돌아올 곳은 같은 사이트 경로만 허용합니다(`safeNext` — 다른 사이트로 보내는 열린 리디렉션 금지).
     - 이동 직전에 표시(`aud.login.redirecting`)를 남겨 둡니다. 돌아왔을 때 응답을 팝업 응답으로 오인하지 않게 하기 위해서입니다.
     - 실패하면 사유를 `/login?reason=`에 담습니다(만료·동의 필요·리디렉션 주소 미등록·역할 없음·기타).
   - **범위 막대**: 본문 맨 위 한 줄(`ScopeBar`)에 구독 › 클러스터를 둡니다.
     - 화면마다 무엇을 보여 줄지는 `navConfig` `PAGE_SCOPE`가 정합니다.
     - 선택은 모든 화면이 함께 씁니다(`lib/scopeStore`, 탭마다 sessionStorage).
     - 화면마다 있던 선택 상자는 지웠습니다. 범위가 바뀔 때 비워야 하는 화면 상태는 `useOnChange`로 비웁니다(VNet 트래픽의 VNet, AKS 보안 점검의 선택, AKS 클러스터의 필터).
4. **왼쪽 메뉴 + Ctrl+K 빠른 이동 + '오늘의 상태' 첫 화면** — 2026-11-10 완료.
   - **왼쪽 메뉴**: 1100px 이상에서는 왼쪽에 고정하고(`--rail-width` 248), 위쪽 막대에는 찾기와 계정만 둡니다. 좁은 화면은 ☰ 서랍입니다.
   - **Ctrl+K**: 어디서나 화면을 찾습니다.
     - 화면 목록은 `navConfig`에서 오며, 동작은 언어·화면 밝기·간격 바꾸기입니다.
     - 입력한 단어가 모두 들어 있는 화면만 남기고, 이름에 걸린 화면을 먼저 보여 줍니다(`lib/commandPalette`).
   - **오늘의 상태**: 개요 맨 위에 둡니다.
     - 확인 안 한 알림·리소스 상태·보안 권고에서 손볼 곳을 한 문장으로 보여 줍니다(`lib/todayStatus`).
     - 읽지 못한 출처는 0으로 세지 않고 '확인 못 함'으로 표시합니다.
5. **다크 모드 · 조밀 보기** — 2026-11-10 완료(켜는 방식).
   - 메뉴 › 설정에서 화면(밝게 · 어둡게 · 시스템)과 간격(편안함 · 조밀)을 고르고, 이 브라우저에 저장합니다(`lib/displayPrefs`).
     - `<head>` 스크립트가 첫 화면이 그려지기 전에 적용해, 밝은 화면이 잠깐 비치지 않습니다.
   - 어둡게는 기본값이 아니라 고르는 사람만 켭니다. 확대·축소하는 그림은 밝은 종이를 그대로 씁니다(`--canvas-rgb`·`lib/palette.ts`).
   - 조밀은 패널 머리 48 · 꼬리 36 · 안쪽 여백 12 · 행 40입니다.
6. **남은 화면 · 그림 카드 12px · 라이브 상세 패널** — 2026-11-10 완료.
   - **그림 카드도 12px**
     - 캔버스 토큰 `--canvas-text-xs`·`sm`을 12px로 올렸습니다. 확대·축소 SVG와 React Flow 라벨도 12로 맞췄고, 예외는 draw.io 내보내기 파일 하나입니다.
     - 카드 바깥 크기는 그대로입니다(라이브 220×100 — 줄 높이 20/16/12 안에 들어감, 긴 줄은 …). 서비스 맵·VNet 맵 카드만 높이 66 → 80입니다(`NET.CARD_H` — 12px 네 줄 + 줄 높이 1.25).
     - 글자 폭을 어림하던 계산도 12px 기준으로 고쳤습니다: 공격 경로 라벨 `textWidth`(라틴 7.1·한글 12), 구성도 머리글 배지(7.4·12.5)·CIDR(7.4).
     - 원 안의 기호 배지(!·?·개수)는 원을 키웠습니다(r 8~9).
   - **라이브 상세 패널**: 키트 패널과 같은 모양입니다.
     - 불투명 + 떠 있는 그림자, 안쪽 여백 `--panel-pad`, 제목 16/600.
     - 띠 높이 40, 선은 `--border`, 행 32.
     - Portal은 키트 작은 버튼 모양, 태그는 칩 모양입니다.
   - **모든 화면 공통 정리**
     - 흐림 + 반투명 배경 → 불투명 패널(테스트로 흐림 금지).
     - 반투명 잉크 글자(0.45 ≈ 3.4:1) → 글자 토큰 136곳(테스트로 금지).
     - 대문자 + 넓은 자간 라벨 제거(31·44곳).
   - **화면별**
     - AKS 보안 점검: 패널 머리 56 · 카드 테두리 · 위험 표시는 왼쪽 굵은 띠 대신 위쪽 2px 선.
     - Pod 트래픽: 요약 카드 = Stat 모양, 상세 패널 = 키트 머리.
     - 리소스 상태 이벤트 탭: 숫자 카드 Stat 4개.
     - 범위 막대: 보여 줄 것이 없으면(로그아웃) 빈 줄 대신 숨김.

## 8. UI 키트 (`components/ui`)

| 부품 | 규칙 |

| `Segmented` | 32 높이, 고른 것 = 진한 바탕 + 흰 글자 |
| `Notice` | 화면당 하나. 1px 테두리 + 옅은 바탕 + 기호, 굵은 왼쪽 띠 없음. `action` = 오른쪽 버튼 |
| `CodeBlock` · `CopyButton` | 설정 조각·명령 — 복사 버튼과 함께 |
| `Toolbar` | 탭 맨 위 한 줄 — 왼쪽 보기 전환·필터, 오른쪽 기준 시각·기간 칩. 알림 상자가 아님(그래서 '알림 하나' 규칙을 지킴) |

**같은 줄 규칙**: 아래 줄의 경계는 위 카드의 경계 위에 놓입니다. 숫자 카드 4개 = 3칸씩이면 아래는 6+6 또는 9+3, 숫자 카드 3개면 4+8. 한쪽에 꼬리가 있으면 다른 쪽에도 둡니다.

**SLO 탭**(첫 적용): 위에 보기 전환 [서비스 SLO | 목표 설정 가이드]과 기준 시각. 알림은 하나만 띄우고(수집 공백 > 기본값 목표), 숫자 카드는 3칸씩, 서비스 카드는 6칸(2열 — 숫자 카드 경계 위)에 놓습니다. 카드 안에는 SLI 두 개를 나란히 두고, 상세는 꼬리의 버튼으로 엽니다. 가이드 탭의 구성은 다음과 같습니다.
- 4단계(실측 보기 → 팀이 정하기 → 연결 파일에 적기 → 확인)
- 무엇을 재나요: 흔히 쓰는 기준(100ms~5s)마다 실제로 세는 경계를 보여 줍니다(`bucketHints` — 예: 2s는 1.79s로 셈). 경계 전체(약 90개)는 접어 둡니다.
- 지난 기간 실측과 '지킨 단계'(없음 = 90%도 못 지킴 → 기준 시간을 늘리거나 원인부터)
- 어디에 적나요: 온프렘 `~/aud-runtime/config/connections.json` + `audctl restart` / Helm `connections` + 자동 재시작. 초안(`sloConfigDraft`)을 복사할 수 있습니다. 초안은 지킨 단계보다 **한 단계 낮게** 잡아 예산에 여유를 두고(`draftTarget`), 서비스 하나를 한 줄로 쓰며, 상자 안에서 스크롤됩니다.
- 항목 설명 — `excludeUris`는 uri 태그와 **정확히 같은 문자열**로 씁니다(패턴 아님).
- 계측 안 된 워크로드 + Micrometer 설정

## 7. 새 화면을 만들 때

- 글자 크기·굵기·모서리·그림자는 토큰만 씁니다. 숫자를 쓰면 `designTokens.test.ts`가 실패합니다.
- 색은 토큰 또는 `rgba(var(--x-rgb), a)`로 씁니다(`palette.test.ts`).
- 새 캔버스(확대·축소되는 그림)를 만들면 그 파일을 테스트의 `CANVAS_CSS`·`CANVAS_TS`에 이유와 함께 넣습니다.
