# 네트워크 경로 — 사용자 장치에서 SaaS까지, 홉별 지연·손실

메뉴 **네트워크 › 네트워크 경로**(`/network-path`)입니다. Datadog의 *End User Device Monitoring + Network Path*에 해당합니다. 사용자의 장치에서 SaaS(예: Microsoft 365 로그인)까지 네트워크 경로를 홉마다 재고, 지연·손실과 그 이력을 보여 줍니다.

> **5살 비유**: 집에서 학교까지 가는 길에 신호등이 몇 개 있고, 어느 신호등에서 오래 기다렸는지 적어 오는 숙제예요. 숙제는 아이(장치)가 직접 걸으면서 적고, 선생님(대시보드)은 그 공책을 받아서 어디가 막히는지 그림으로 보여 줘요. 신호등 하나가 "대답을 안 했다"고 해서 길이 막힌 건 아니에요 — 그 뒤 신호등들이 모두 대답하면 길은 잘 뚫려 있는 거예요.

## 1. 왜 장치에서 재나

| 위치 | 홉별 traceroute | 이유 |
|---|---|---|
| 브라우저 | 불가 | TTL을 정할 수도, ICMP를 받을 수도 없음(HTTP 타이밍만) |
| 대시보드 컨테이너 | 불가 · 의미 없음 | 셸·NET_RAW 없는 강화 이미지(65532), 그리고 경로의 시작이 사용자 장치가 아니라 클러스터 |
| **사용자 장치** | 가능 | Windows: .NET `Ping`에 TTL 지정(`IcmpSendEcho` — 관리자 불필요, 언어 설정과 무관) · macOS/Linux: `mtr` |

Datadog은 장치에 에이전트를 깝니다. 여기서는 **측정 스크립트**(`scripts/netpath-probe.ps1`, 화면에서 복사)를 장치에서 실행하고 결과(JSON)를 올립니다. 대시보드는 인터넷을 직접 재지 않습니다.

## 2. 측정 → 올리기 → 계산

화면은 세 단계(1 대상 → 2 장치에서 실행 → 3 결과 올리기)입니다.

**무엇을 대상(`-Target`)으로 넣나**: 사용자가 느리다고 말하는 서비스의 **주소창에 보이는 이름(호스트)**입니다. `https://`와 `/` 뒤의 경로는 필요 없습니다. 주소를 통째로 붙여 넣으면 화면이 이름만 골라 쓰고 그렇게 했다고 말합니다(`lib/netPathView.ts` `targetOf` — 스킴·사용자·포트·경로·질의·조각을 빼고 소문자로 바꿈). 점이 없는 한 단어(예: `intranet`)는 장치의 DNS 검색 목록에 따라 다른 곳으로 갈 수 있어 받지 않습니다. IPv6는 스크립트가 아직 지원하지 않습니다. 자주 재는 대상은 버튼으로 고릅니다(Microsoft 365 로그인 `login.microsoftonline.com` · Outlook · Teams · Azure Portal · GitHub, 그리고 대시보드가 로컬 주소가 아닐 때 이 대시보드). 고른 이름으로 실행 명령이 바로 만들어집니다. 스크립트는 '스크립트 받기'로 다운로드 폴더에 저장합니다(BOM 포함 — Windows PowerShell 5.1이 BOM 없는 파일을 ANSI로 읽기 때문).

| 붙여 넣은 값 | 재는 대상 |
|---|---|
| `https://Outlook.Office365.com/mail/inbox?x=1` | `outlook.office365.com` |
| `http://user:pw@portal.example.com:8443/a` | `portal.example.com` |
| `203.0.113.10` | `203.0.113.10` |
| `intranet` | 받지 않음 — 점이 있는 이름이나 IPv4 |

1. **스크립트**(형식 `aud-netpath/2`, 2026-11-19 — Datadog Network Path의 기본값을 따름: `traceroute_queries` 3 · `max_ttl` 30 · `timeout` 1000 ms · 종단 탐침). 측정 1회는 다음과 같습니다(관리자 권한 불필요, 약 20–40초).
   - **traceroute `-Queries`(3)번**: TTL 1부터 TTL마다 ICMP 1개를 보내고, 탐침 하나하나를 그대로 남깁니다(TTL · 응답한 주소 · 그 탐침의 시간 · 응답 종류 'TTL 만료/목적지/무응답'). 그래서 **어느 홉 다음에 어느 홉이 왔는지**가 남고, 다중 경로 그래프가 사실이 됩니다. v1은 TTL별 주소 개수만 있어 이것을 알 수 없었습니다. traceroute는 목적지에 닿거나, `-MaxHops`(30)에 이르거나, `-MaxUnknown`(8)개 TTL이 연속으로 무응답이면 멈춥니다. .NET은 'TTL 만료' 응답의 왕복 시간을 0으로 줍니다(이 PC에서 실측). 그래서 탐침마다 스톱워치로 잽니다.
   - **종단 탐침 `-E2e`(20)번**: 기본은 `-Port` 443 **TCP 연결**입니다. SaaS 주소 중 ICMP에 답하지 않는 곳이 많아, ICMP만 쓰면 '도달 못 함'으로 잘못 보입니다. `-E2eProtocol icmp`로 바꿀 수 있습니다. 시간은 보낸 순서대로 남기고, 잃은 탐침은 `-1`로 둡니다. Datadog의 기본은 50번입니다.
   - **연결**: 대상에 갈 때 장치가 쓰는 연결의 종류와 속도만 남깁니다(.NET `NetworkInterfaceType` · Mbps). UDP `Connect`로 경로만 고르고 패킷은 보내지 않습니다. 이름·주소·MAC은 남기지 않습니다.
   - **`-Lookup`(선택, 기본 끔)**: 공인 홉마다 이름(PTR)을 장치의 DNS에, AS를 Team Cymru DNS(`<역순>.origin.asn.cymru.com`, `AS<n>.asn.cymru.com` TXT)에 묻고 **TXT 원문**을 남깁니다. 홉 주소가 그 두 곳으로 나가므로 화면에도 그렇게 적었습니다.
   - **반복 `-Repeat` · `-IntervalSec` · `-OutFile`**: 측정 1회가 JSON 한 줄이고, 파일에 이어 붙습니다. 그 파일 내용을 그대로 올리면 여러 측정이 됩니다(시간 막대).
2. **mtr**: `mtr --json -n -c 10 <대상>` 보고서를 그대로 받습니다. mtr JSON에는 요약값(Best·Avg·Wrst·Loss%)만 있어 그대로 씁니다. 호스트 `???` = 응답 없음.
3. **올리기**: 화면에 붙여 넣으면 `POST /api/netpath/runs`로 갑니다(로그인 사용자가 자기 장치에서 잰 것).
   - 받는 모양: JSON 하나, JSON 배열, 한 줄에 측정 하나(`parseNetPathMany`). 최대 900KB · 200회이고, 한 줄이라도 틀리면 전부 거부합니다.
   - 서버가 계산합니다(`services/netPath.ts`).
   - TTL별 홉: v2는 traceroute를 합쳐 셉니다. 보냄 = 그 TTL까지 간 traceroute 수, 손실 = (보냄 − 받음) / 보냄, 지연 = 받은 탐침의 최소·평균·최대, 주소 = 가장 많이 답한 것.
   - 종단(`e2eOf`): 손실 = 잃은 탐침 / 보낸 탐침. 지연 = 받은 탐침. **지터 = 이웃한 두 응답의 RTT 차이 평균**(RFC 3550·5481의 IPDV, 평활 없음 — 응답 쌍이 2개 미만이면 없음).
   - AS(`hopInfoOf`): Team Cymru TXT를 해석합니다. 여러 AS가 알린 대역은 첫 AS를 씁니다. 다른 AS의 이름은 붙이지 않습니다.
   - 범위: 사설(RFC 1918) · CGNAT(100.64/10) · 공용.
   - 응답 `{runs}`.
4. **저장**: `<AUD_ARRANGEMENT_DIR>/netpath/runs.json`(없으면 메모리 + 화면 경고), 측정 시각 순 최신 500개. 지우기는 운영자(`DELETE /api/netpath/runs?id=`).

**대시보드가 하지 않는 것**: 주소의 소유자·위치·이름을 대시보드가 바깥에 묻지 않습니다. AS는 사용자가 `-Lookup`을 켠 측정에만 있고, 그때 묻는 쪽은 장치입니다.

## 3. 화면 — 목록 → 경로(Path View · Analysis) + 시간 막대

Datadog Network Path의 Explorer와 같은 순서입니다.

**목록**(대상 · 장치): 대상마다 가장 최근 측정의 도달(측정 n/m) · 종단 지연 · 손실 · 지터 · 홉 · 측정 수를 보입니다. 행을 누르면 그 경로가 열립니다. 머리에는 장치 → 대상과 연결(예: Wi-Fi · 287 Mbps)이 있고, 탭은 **[경로 보기 — 네트워크 토폴로지 | 분석 — 홉별 지표 개요]**입니다.

**시간 막대**(`HealthBar`, 두 탭 공통): 이 장치 × 대상의 측정마다 표시 하나를 시각 축에 둡니다.
- 위 줄: 종단 지연. 막대 높이로 보입니다.
- 아래 줄: 도달. 색은 사실로만 칠합니다 — ■ 종단 탐침이 하나도 닿지 못함 · ▲ 손실 있음 · ● 정상.
- 고르기: 누르면 측정 1회를 고르고, 끌거나 Shift+누르기로 구간을 넓힙니다. 키보드는 ←/→ 이동, Shift+←/→ 넓히기, Home/End.
- 버튼 '전체 측정' · '최근 1회'가 있습니다. 기본은 최근 1회입니다.

경로와 분석은 **고른 측정을 합친 값**입니다.

**경로 보기**(`PathGraph` + 순수 `lib/netPathGraph.ts`):

| 요소 | 규칙 |
|---|---|
| 노드 | TTL마다 응답한 주소 하나(같은 주소가 다른 TTL에서 답하면 다른 노드). 목적지는 하나. 무응답 TTL = '응답 없는 홉' `*` |
| 선 | **같은 traceroute의 이웃한 응답**만 잇습니다. 굵기 = 그 길로 간 traceroute의 비율, 숫자 = 늘어난 지연(노드 평균 − 앞 노드 평균, 0 이하 = '<1 ms'). |
| 색 | 초록 = 측정된 경로. 빨강 = 목적지까지 이어지는 손실(`pathView` 규칙). 주황 = **내가 정한 기준**(ms, 기본 없음) 이상. 점선 = 측정되지 않은 연결(응답 없는 홉을 건너뜀 '*n', 또는 옛 형식) |
| 카드 | 이름(PTR) 또는 주소 · AS(조회했을 때) 또는 주소 종류 · 평균 지연 · TTL 무응답 % · 지나간 횟수 n/N(전부가 아닐 때). 목적지 카드는 도달 여부 · 손실 · 지연(종단 탐침 기준) |
| 도구 | 홉 찾기(주소·이름·AS) · **응답 없는 홉 숨기기**(기본 켬, 개수 표시) · **묶는 기준** IP 주소 / AS / 구간(내 네트워크·경유·목적지) · **모든 묶음 접기** · 선 강조 기준(ms) |
| 묶음 | 이웃한 TTL의 응답 홉이 모두 같은 키일 때 묶습니다. 응답 없는 홉은 그 사이에 끼워 넣습니다. 홉 1개는 묶지 않습니다. 접으면 카드 하나가 되고, 이 카드는 들어온 traceroute 수 · 구성원 지연 범위 · 나가는 쪽 평균을 보입니다. 들어가는 선은 첫 홉까지만 잽니다. |
| 상세 | 카드를 누르면 옆에 사실이 보입니다: TTL · 주소 · PTR · AS · 대역 · 주소 종류 · 지나간 traceroute n/N · 평균(최소–최대) · 이 TTL 무응답 · 판정 설명. 목적지는 종단 탐침(TCP 443) 응답 · 손실 · 지연 · 지터와 traceroute(ICMP) 도달을 따로 보입니다. |
| 화면 맞춤 | 경로 전체가 0.7배 이상으로 들어가면 전체를 보입니다. 아니면 0.7배로 출발점(왼쪽)부터 보입니다(12px 글자 ≥ 8.4px). 높이는 가장 많은 행에 맞춥니다(240–560px). |

옛 형식(v1·mtr)이 섞이면 TTL마다 가장 많이 답한 주소만 점선으로 잇고, 그렇다고 적습니다. 어느 홉 다음에 어느 홉이 왔는지는 기록되지 않았기 때문입니다.

**분석**(`AnalysisView`):
- **숫자 6개**:
  - 종단 지연(최소–최대)
  - 패킷 손실(응답 n/N)
  - 지터
  - 도달한 측정 n/m
  - 홉 수
  - 경로 수(traceroute마다 주소 순서가 다른 경우 — 다중 경로·경로 변경)
- **종단 지표 추이**: 지연 · 손실 · 지터 · 홉 수 4개를 시간에 따라 봅니다. 그림마다 계열·축이 하나이고, 고른 구간은 음영입니다. 점을 누르면 그 측정을 고릅니다.
- **홉별 지연 그림**: 기존 그림이며, 합친 값입니다.
- **홉별 표**: TTL · 홉(주소/PTR) · AS · 지나감 n/N · 평균 · 최소–최대 · TTL 무응답 · 증가.
- **'바로 앞 같은 길이 구간과 비교'**: 측정 1회를 골랐으면 그 앞 측정과 비교합니다. 앞 구간 · 차이 · 새 홉 · 사라짐 · 공통을 보이고, 숫자 카드 아래에 차이가 붙습니다.
- **측정 목록**: 시각 · 지연 · 손실 · 지터 · 홉 · 이전과 같음/바뀜 · 연결 · 지우기(운영자).

**판정**: 네트워크 엔지니어가 mtr·pathping 결과를 읽는 방식(`lib/netPathView.ts`)을 따릅니다.

| 판정 | 조건 | 화면 |
|---|---|---|
| 경로 손실 | 손실이 그 홉부터 **목적지까지 이어짐**(응답 없는 홉은 건너뜀) | ▲ 주황, 선 빨강 |
| ICMP 제한 | 중간 홉에만 손실, 뒤 홉·목적지는 정상 | ◌ 색 없음 — 라우터가 자기에게 오는 ICMP에 답을 줄인 것, 경로 손실 아님 |
| 응답 없는 홉 | 그 TTL의 탐침 모두 무응답 | `*` 점선 카드, 숨기기 |
| 목적지 도달 | 종단 탐침이 하나라도 응답(없는 옛 형식은 traceroute 도달) | 목적지 카드 ● / ■ |

## 5. 남은 일

- **정기 측정 자동 올리기**: 장치가 API 토큰을 얻는 길(디바이스 코드 로그인 등)이 필요합니다. 지금은 반복 측정 파일을 사람이 올립니다.
- **TCP traceroute**: 흐름별 부하 분산 때문에 TCP는 ICMP와 다른 길로 갈 수 있습니다. 관리자 권한 없는 Windows에서는 라우터의 TTL 만료 응답을 받을 수 없어 홉은 ICMP 경로입니다. 종단은 TCP로 잽니다.
- **다중 경로 전수 탐색**(MDA·Paris traceroute): 흐름 식별자를 고정·변경하는 기능이 아직 없습니다. .NET Ping은 ICMP 식별자를 고르지 못합니다. 지금 보이는 갈래는 traceroute 3번이 우연히 지나간 길입니다.
- **IPv6**: 스크립트가 아직 지원하지 않습니다.
- **mtr 실측**: macOS·Linux에서 아직 재보지 않았습니다.
