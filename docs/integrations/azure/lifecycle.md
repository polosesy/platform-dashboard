# 자격 증명 교체 · 연결 해제

> **대상**: 플랫폼 관리자, 고객 테넌트 관리자 · **소요 시간**: 10분

## 10. 자격 증명 교체

비밀 값·인증서는 만료 전에 **겹치게** 교체해 끊김이 없게 합니다. 교체 후 [verify.md](./verify.md)의 점검을 실행하세요.

### 인증서 (권장)

1. 새 인증서를 앱에 **추가**합니다(기존 것은 그대로): Entra ID → 앱 등록 → 인증서 및 비밀 → 인증서 업로드. 또는 `az ad app credential reset --id <APP_ID> --cert @new.pem --append`.
2. 플랫폼 서버의 PEM 파일을 새 것으로 바꾸고(같은 경로 `AUD_PLATFORM_CERT_PATH` / `certificatePath`) API를 재시작합니다.
3. 점검이 `정상`이면 옛 인증서를 앱에서 삭제합니다.

### 비밀 값

1. 새 비밀 값을 **추가**합니다: `az ad app credential reset --id <APP_ID> --append --years 1` (출력된 값은 한 번만 보임).
2. 환경 변수(`AZURE_AD_CLIENT_SECRET` 또는 `AUD_CONN_<KEY>_SECRET`)를 새 값으로 바꾸고 API를 재시작합니다.
3. 점검이 `정상`이면 옛 비밀 값을 삭제합니다.

Lighthouse 연결(C)은 플랫폼 자격 증명을 쓰므로 고객 쪽 교체 작업이 없습니다.

## 11. 연결 해제

| 쪽 | 할 일 |
|---|---|
| 플랫폼 | 연결 파일에서 항목 삭제 → API 재시작(메모리 캐시도 비워짐). `servicePrincipal`이면 `AUD_CONN_<KEY>_SECRET`·인증서 파일 삭제 |
| 고객 (B) | 앱 등록 삭제(또는 비밀 값·인증서 삭제) + 역할 할당 제거 |
| 고객 (C) | 포털 **서비스 공급자 → 위임**에서 위임 삭제, 또는 `az managedservices assignment delete` |

해제 후 플랫폼에 남는 데이터는 없습니다(디스크 저장 없음). 감사 로그(stdout을 수집하는 곳)에는 연결 키가 남습니다.

> **5살 비유**: 새 열쇠를 먼저 만들어 맞는지 확인하고 나서 옛 열쇠를 버려요. 친구 관계를 끝낼 때는 맡긴 열쇠를 돌려주고(플랫폼), 문에 붙인 이름표도 떼요(고객).
