### FAQ

**Q. 사용자 개인의 Azure 권한을 아예 쓸 수 없나요?**
A. 쓸 수 있습니다. 연결을 `delegated`로 두면 그 연결은 로그인한 사용자의 권한(OBO)으로 읽습니다. 고객이 상시 서비스 주체를 원하지 않을 때만 권장합니다. 한 요청 안에서 방식이 섞이지 않습니다.

**Q. 감사 기록은 어디에 남나요?**
A. Azure 쪽 활동 로그에는 연결의 서비스 주체 이름으로 남고, "어느 사용자가 봤는지"는 플랫폼 감사 로그(`AUD_AUDIT_LOG=stdout`, 프로덕션 기본)에 남습니다. stdout을 로그 수집기로 보내세요.

**Q. 비밀 값 대신 관리 ID를 쓸 수 있나요?**
A. 워크로드 ID 페더레이션(관리 ID → 앱)은 후속 작업입니다. 지금은 인증서를 권장합니다.

**Q. 고객이 동의 버튼만 누르는 방식(멀티 테넌트 앱)은?**
A. 후속 작업입니다. 지금은 Lighthouse(C) 또는 고객 서비스 주체(B)를 씁니다.

**Q. 로컬 개발에서 로그인 없이 실데이터를 보려면?**
A. `AUD_ANONYMOUS_SP=true`(루프백 바인드 필수, 연결 1개일 때만). 프로덕션에서는 쓰지 마세요.

**Q. 역할 없이 로그인하면?**
A. 개발에서는 `AUD_DEFAULT_ROLE`(기본 `viewer`)로 동작하고 배지에 `*`가 붙습니다. 프로덕션은 `none`만 허용되어 `403 no_platform_role`입니다.

> **5살 비유**: 열쇠는 놀이공원 금고에만 있고, 누가 어느 창고를 봤는지 공책에 적어요. 쪽지에 열쇠 번호를 절대 쓰지 않고, 열쇠 하나가 안 맞는다고 마스터키를 꺼내지 않아요.
